## 摘要
在目标导向的具身导航中，智能体必须在未见环境中定位指定目标，此时3D场景理解与导航推理必须协同工作。当前方法通过文本将3D场景信息传递给视觉语言模型（VLM），表明我们测试的配置中存在表示差距；一个受控消融实验证实，直接嵌入级传输显著优于评估的文本序列化格式。我们提出了SoftNav，它通过轻量级投影仪将实体级3D连续表示（每个检测到的对象或前沿对应一个标记）作为软标记注入到VLM的隐藏空间中。在3D编码器和VLM被冻结的情况下，仅需约1,200个样本和约1,700万个可训练参数。在HM3D-OVON上，SoftNav在三个数据划分上分别实现了74.2%/68.3%/66.7%的成功率（SR），在SR和SPL上均超越了所有先前方法；相同的导航策略零样本迁移至GOAT-Bench（67.2% SR）、SG3D（47.2% s-SR）以及现实世界机器人部署，无需重新训练或架构修改。将3D场景标记直接注入VLM弥合了表示差距，实现了以最少训练的可迁移导航。

## Abstract
In goal-directed embodied navigation, where an agent must locate a specified target in an unseen environment, 3D scene understanding and navigation reasoning must work in concert. Current approaches transmit 3D scene information to vision-language models (VLMs) through text, suggesting a representation gap in our tested configurations; a controlled ablation confirms that direct embedding-level transfer significantly outperforms the evaluated text serialization formats. We introduce SoftNav, which injects entity-level 3D continuous representations -- one token per detected object or frontier -- into a VLM's hidden space as soft tokens through a lightweight projector. With the 3D encoder and VLM frozen, only ~1,200 samples and ~17M trainable parameters are needed. On HM3D-OVON, SoftNav achieves 74.2%/68.3%/66.7% SR across three splits, surpassing all prior methods in both SR and SPL; the same navigation policy transfers zero-shot to GOAT-Bench (67.2% SR), SG3D (47.2% s-SR), and real-world robot deployment without retraining or architectural modification. Injecting 3D scene tokens directly into VLMs bridges the representation gap, enabling transferable navigation with minimal training.

# SoftNav：将3D场景标记注入视觉语言模型以进行具身导航

## 1. 核心问题与整体含义（研究动机和背景）

- **核心问题**：在具身导航中，智能体需在未见环境中定位指定目标，但当前方法通过文本序列化（如坐标字符串、场景图文本）将3D场景信息传递给视觉语言模型（VLM），导致**表示差距**（representation gap）——连续的高维几何-语义特征在离散文本化过程中丢失大量信息。
- **背景**：主流范式包括模块化方法（如SemMap、MTU3D）和VLM方法（如NavGPT、NaVid），但前者缺乏VLM推理能力，后者缺乏结构化3D感知。两者结合时通常依赖文本接口，该接口的信息损失从未被量化。
- **整体目标**：量化表示差距，并提出一种直接注入连续3D表示（软token）的方法，以最小训练代价实现高效、可迁移的导航。

## 2. 方法论：核心思想、关键技术细节

### 核心思想
- 使用专用3D场景编码器（PQ3D）提取每个检测物体或前沿的768维query embedding，通过轻量MLP投影器映射到VLM的2048维隐藏空间作为**软token**，每个软token编码几何、语义和空间关系信息。
- VLM同时接收视觉记忆token、软token和文本指令，生成目标坐标，然后snap到最近的前沿（利用占据图-前沿检测），确保可达性。

### 关键技术细节
- **3D场景编码器**：PQ3D（来自MTU3D），从流式RGB-D观测中增量式3D实例分割，维护物体银行，检测前沿，输出统一实体嵌入 {q_i} ∈ R^{N×768}，N = N_obj + N_frontier。冻结不训练。
- **视觉流**：DINOv3提取每帧特征，经PatchMerger压缩为15个token；滑动窗口保存最近K=16帧（共240 tokens）作为视觉记忆。
- **软token injection**：MLP投影器结构：768 → 1408 → 2048，含GELU、LayerNorm。将投影后嵌入替换文本模板中的占位符，与视觉记忆和文本token拼接输入VLM。
- **VLM**：Qwen2.5-VL-3B，冻结，仅训练LoRA（r=8, α=32，用于q_proj, v_proj, down_proj, up_proj，~13M参数）和MLP投影器（~4M参数），总计~17M可训练参数。
- **训练数据**：从MTU3D成功episode中蒸馏约1,187个监督样本（每个步骤中教师选中的前沿坐标作为标签），使用自回归下一个token预测损失。
- **前沿决策**：VLM生成坐标 ^c，snap到最近前沿 f*，并添加距离比 guardrail（r=2）防止过远选择。若前沿为空，触发救援回退。
- **算法流程**：见Algorithm 1（每步：视觉压缩 → 3D感知 → 软token投影 → VLM推理 → snap → 执行NavigateTo）。

## 6. 主要结论与发现

- **表示差距被量化**：文本序列化相比直接软token注入导致显著性能损失（ΔSPL +9.2 pp, p<0.0001; ΔSR +7.5 pp, p=0.028），且单纯增加文本丰富度（Rich-Text）或模型容量（LoRA）无法弥合差距。
- **SOTA性能**：在HM3D-OVON三个子集上SR达74.2%/68.3%/66.7%，超越之前最好结果19-26个百分点；SPL也全面领先。
- **零样本迁移能力强**：同一策略无需修改直接迁移到GOAT-Bench（67.2% SR）、SG3D（47.2% s-SR）和真实机器人（19/30成功），展现任务间nav语义的通用性。
- **轻量高效**：仅需~17M参数和~1.2k样本训练，即可获得高泛化能力。
- **软token优势来源**：连续嵌入保留了几何-语义结构，而文本序列化完全破坏该结构（图4 UMAP可视化）。

## 7. 优点

- **新颖性**：首次将实体级3D场景编码器输出直接作为软token注入VLM，而非2D图像块或文本序列。
- **简洁高效**：冻结大部分组件，仅小规模可训练，训练数据极小，但取得大幅性能提升。
- **强泛化**：单一策略零样本跨benchmark和到真实世界，体现学习到的导航语义的内在通用性。
- **严谨消融**：通过控制变量实验直接量化了表示差距，并排除模型容量、文本丰富度等混淆因素，因果推断有力。
- **真实部署验证**：在室内外环境中均取得了可观成功率，验证了sim-to-real迁移可行性。

## 8. 不足与局限

- **训练数据规模过小**（仅~1,200样本），可能限制潜在天花板；作者也提及扩大训练集可能进一步提升空间适应。
- **仅使用PQ3D一种3D编码器**，未验证与其他编码器（如不同backbone的3D-VLM）的兼容性，泛化性存疑。
- **SPL在零样本场景略低于最强基线**（如GOAT: 29.0% vs 30.5%），存在SR-SPL trade-off，长路径问题在novel布局中突出。
- **推理速度较慢**（~1s/step），主要瓶颈在PQ3D和VLM，不适用于实时或高帧率场景。
- **token选择策略未充分优化**：硬top-K选择器性能不如全注入，可能因梯度阻断；可考虑软选择或可微注意力。
- **真实世界测试规模有限**（仅30 trials，3个环境），且未提供详细失败分析（如感知失败与决策失败比例）。
- **未讨论对动态环境的适应性**（如移动障碍、光照变化等）。
